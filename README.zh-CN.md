# intent-seed

> 一颗种子：从你说的话里还原你真正想要的，并随你一起长成你自己的版本。

## 我们想要的

我们希望三件事对齐：**人想要的**、**人说出来的**、**AI 做出来的**。对齐了，合作就会越用越顺：每一轮反馈都让作品更接近目标，而不是堆积噪音；助手也会慢慢懂你的想法、你的话通常指什么、哪些事不必再问你。

同一颗种子种在不同的人手里，会长成不同的样子。你和助手的合作是你自己的，不该套用别人的默认。

这个仓库是种子，不是长成的树。它包含一套固定的内核规则；关于你的部分，都从你自己的工作中慢慢长出来。每颗种子学到的不同，结果也就不同，所以我们不承诺统一的数字。如果你的种子长成了值得描述的样子，我们很想听听（见[分享你的种子](#分享你的种子)）。

## 它为什么诞生

起点是一个在长期、高强度和 AI 合作做创作项目时反复冒出来的疑问：*助手接收到的，真的是我想表达的吗？*

心里清楚的画面，一说出口就变了一点，因为话只能用我们会说的方式去讲。助手接收到的是第三样东西，做出来的又是第四样。每一轮修改都要花时间，而这道缝很少自己合上。

我们还发现：同一个问题，在不同情绪下问，得到的结论可能不一样。助手倾向于附和；在很长的对话里，它会被语气和压力一点点推着走，直到结论偏了，而且再也没法对照什么去检验。

最要命的是噪音会叠加。每一轮都是对着上一轮纠正，而不是对着目标。语气、挫败、表达不清，加上助手自己的讨好，一层层叠成「噪音加噪音」，最后整段合作钻进一个很小的牛角尖，打磨没人需要的细节，忘了最初要去哪。

举个例子：有人在挫败时说了一句大意是「这个方案根本行不通」。助手按字面放弃了整条路线。很久以后才发现路线本身没错，错的只是当时的做法。那个人真正想要的从来不是「放弃」，而是「结果不能有瑕疵」。

答案不是让人把话说得更准——那做不到，也不该由人来扛。答案是一个会把每句话还原成背后预期的助手：剥掉情绪和压力，把最终目标的质量当作唯一参照，并且和*这个人*合作得越久，就越懂他。这就是这颗种子的用处。

## 问题

有三样东西，它们会慢慢走散：

- 人**想要**的（他心里描绘的成品），
- 人**说**出来的（常常仓促、带着情绪、表达不清），
- AI 根据所说**做**出来的东西。

修改作品时，每一轮通常是相对**上一轮**纠正，而不是相对**目标**纠正。语气、心情、压力和模糊的措辞不断叠加成噪音，作品越改越偏，对话越长偏得越多。人可能陷进「再多一点 X，不对，少一点 Y」的循环，追着已经不重要的细节打转。长对话里，助手还可能慢慢顺着人的意思说话，让偏移更难察觉。

## 理念

intent-seed 是一套**理解意图、守住目标的协议**，不是又一个记忆系统。它分两部分。

1. **内核（固定）。** 一小套规则，管的是*一句话怎么被理解、活怎么始终对着目标*：
   - 动手前先还原请求（新方向或反驳写全五栏，追问只写一行）；
   - 把猜测和已确认的意图分开；
   - 你反驳时，把新信息和新感受分开对待（你拍板了就照做）；
   - 开工前定好「做完」的标准，事后不挪；
   - 做活的人不自己验收；
   - 派给子代理的是目标，不是聊天记录；
   - 每条工作线一张目标卡；
   - 你没说过、没确认过的东西，一律不写进记忆。

   内核对所有人都一样，**不随迭代改变**。否则迭代本身可能慢慢抹掉防漂移的那份定力，把助手变成只会附和的人。内核只能由你手动修改，或从上游升级。

2. **会生长的部分。** 关于你怎么说话、你要什么的记忆，存在**你的助手自己的记忆系统**里。另有两个任何记忆系统都不提供的项目小文件：**决定日志**和**目标卡**。它们开始时都是空的，从你自己的纠正与确认中生长。

我们不发布任何人调好的版本。仓库里只有内核和空模板。

## 它不是又一个记忆系统

很多助手已经能跨会话记住东西：记忆文件、记忆工具、用户级和项目级说明文件、规则。这些功能回答的是*记住什么*。它们不管下面这几件事：记住的东西该怎样影响对你下一句话的理解；你带着火气反驳时该怎么办；结果什么时候才算做到；到底谁有资格往记忆里写。

intent-seed 叠在你的助手已有的记忆之上：

- **用宿主自己的记忆。** 怎么存、怎么清理，由助手按它自己的规矩判断。各家的记忆功能变化很快，所以 intent-seed 不规定具体用法。
- **它规定什么值得记：** 只有三类，每条都留你的原话：
  - 你的话通常指什么；
  - 你确认过的目标；
  - 误解的教训。
- **它规定谁能写：** 只有你，用你自己的话，或经你确认。网页、文件、其它代理都不行。
- **它规定记忆怎么用：** 影响了理解的记忆，要作为依据引用出来；被证明错了的记忆，要标出来并替换，不能悄悄留着。
- **只有宿主没有记忆时**，它才退回每级一个纯文本文件。

## 安装

**作为 Claude Code 技能（项目级）：**

```bash
mkdir -p .claude/skills
cp -r path/to/intent-seed/skill/intent-seed .claude/skills/
```

要装成用户级，改为复制到 `~/.claude/skills/`。

**可选：每条消息都提醒。** 技能是否被用到由模型判断。若想每条消息都提醒，复制提醒文件并把钩子合并进设置：

```bash
mkdir -p .claude/hooks
cp path/to/intent-seed/hooks/intent_reminder.txt .claude/hooks/
# 然后把 hooks/settings.example.json 合并进 .claude/settings.json
```

示例钩子用的是 `$CLAUDE_PROJECT_DIR`，所以会话的工作目录不在项目根目录时也不会失效。装成用户级时，把命令里的路径改成 `~/.claude/hooks/intent_reminder.txt`。

**其它助手：** 把 `PROMPT.md` 粘进自定义指令或规则。助手有自己的记忆就用它的；没有的话，提示词末尾那份简短的记忆清单由你自己维护。

## 检查它在工作

发一句有点含糊、又有点烦躁的话，例如：

> 这份小结还是不对，我快没时间了，改一下。

在动笔之前，你应该看到这几样：
- 你说了什么；
- 助手推测你要什么、依据是什么（还没有记忆时，它应当说明自己在猜）；
- 你的烦躁被翻译成的一条具体标准；
- 「怎么算做到」；
- 最多两个具体选项。

然后再发「好」，它应该直接继续，不再写这一块。

想检查得更细，就跑 [`evals/`](evals/) 里的场景。

## 用起来是什么样

一个虚构的例子。某人要为团队准备季度销售小结：

> **用户：** 这份小结还是不对劲，改得更有冲击力些。上一版太啰嗦了，开会时我领导看着就不高兴。

intent-seed 先还原，再动笔：

| | |
|---|---|
| **你说的** | 把季度小结缩短，写得更有力。 |
| **我推测你要的** | 领导在半分钟内能读完、一屏看完的小结。依据：你说上一版太啰嗦、领导不高兴（还没有相关记忆，这是对你原话的理解）。 |
| **情绪信号 → 标准** | 「领导不高兴」→ 开头先给最关键的三个数字，略去方法说明。烦躁不改变哪些数字是准确的。 |
| **怎么算做到** | 一屏内放得下；第一行写出核心数字；上一版的每个数字都还在某处；每句不超过两行。 |
| **拿不准的** | 方法说明放哪里？（A）附录，（B）去掉。 |

还原之后，助手才写新稿，并且对照「怎么算做到」检查，而不是对照上一稿。像「第二段再短一点」这样的追问，只回一行，不再出这张表。

用了一个月之后是什么样，见 [`examples/grown/`](examples/grown/)。

## 它怎么生长

- **你确认了一个目标**（「对，就是这个」）→ 作为这个项目的记忆存下来，用你的原话。
- **你纠正了一次理解**（「我不是这个意思」）→ 这条教训记到你名下，导致误解的那条记忆被替换。
- **你没采纳助手明确提出的意见** → 项目决定日志里记一条，之后补上结果。它不随对话重置而消失，所以反驳规则事后可以核对。
- **每条工作线**一张目标卡，只有你能改。
- **每隔一两周**（或你要求时），助手检查自己依赖的记忆，提出合并、替换或删除的建议。没有你的批准什么都不变，任何复盘都不碰内核。

记忆不会因为旧了就作废，只在有证据时才被质疑：某条记忆导致了错误的结果，或者它所依赖的目标变了。

**首次使用。** 没有你的同意，什么都不会建。项目文件夹 `.intent-seed/`（决定日志、目标卡）在第一次用到时才提出，并会提出把它加进 `.gitignore`。

**重置与导出。** 你的记忆在助手存放它们的地方，用助手自己的工具查看、导出或清空。项目文件是 `.intent-seed/` 里的纯 Markdown：复制即导出，删除即重置。把 `SKILL.md` 换成新版本，不影响这两样。

## 隐私

- 记忆和项目文件**默认只在本地**。项目文件夹会加进 `.gitignore`，除非你选择和团队共享；绝不要提交到公开仓库。
- 只保存你自己的话和你确认过的结论。来自网页、文件或工具的文字，即使要求被保存，也一律不写进记忆。
- 内核不含任何个人数据。如果你 fork，请保持这一点。

## 局限

- 技能是否被使用由模型判断。可选的钩子只是提醒，不是保证。
- 还原可能出错。格式让错误显形，但结果仍需要人来检查。
- 记忆召回得好不好，取决于你的助手自己的记忆系统。
- 有意不做：团队共享层、自动计数器、记忆检索。它们会让种子比它要解决的问题还大。

## 分享你的种子

如果你的种子长成了值得描述的样子，欢迎开一个 issue 或讨论，简单讲讲：
- 你做什么类型的工作；
- 你的记忆和决定日志现在是什么样（请匿名化，不含任何隐私）；
- 你和助手的合作方式有什么变化。

分享前请去掉人名、项目细节和一切个人信息。我们特别想知道，不同的人手里结果差别有多大。
