# intent-seed

> 一颗种子：从你说的话里还原你真正想要的，并随你一起长成你自己的版本。

## 我们想要的

我们希望三件事对齐：**人想要的**、**人说出来的**、**AI 做出来的**。对齐了，合作就会越用越顺：每一轮反馈都让作品更接近目标，而不是堆积噪音；助手也会慢慢懂你的想法、你的话通常指什么、哪些事不必再问你。

同一颗种子种在不同的人手里，会长成不同的样子。你和助手的合作是你自己的，不该套用别人的默认。

这个仓库是种子，不是长成的树。它包含一套固定的内核规则，以及一个从你自己的工作中慢慢填满的空个人层。每个人的个人层不同，结果也就不同，所以我们不承诺统一的数字。如果你的种子长成了值得描述的样子，我们很想听听（见[分享你的种子](#分享你的种子)）。

## 它为什么诞生

起点是一个在长期、高强度和 AI 合作做创作项目时反复冒出来的疑问：*助手接收到的，真的是我想表达的吗？*

心里清楚的画面，一说出口就变了一点，因为话只能用我们会说的方式去讲。助手接收到的是第三样东西，做出来的又是第四样。每一轮修改都要花时间，而这道缝很少自己合上。

我们还发现：同一个问题，在不同情绪下问，得到的结论可能不一样。助手倾向于附和；在很长的对话里，它会被语气和压力一点点推着走，直到结论偏了，而且再也没法对照什么去检验。

最要命的是噪音会叠加。每一轮都是对着上一轮纠正，而不是对着目标。语气、挫败、表达不清，加上助手自己的讨好，一层层叠成「噪音加噪音」，最后整段合作钻进一个很小的牛角尖，打磨没人需要的细节，忘了最初要去哪。

举个例子：有人在挫败时说了一句大意是「这个方案根本行不通」。助手按字面放弃了整条路线。很久以后才发现路线本身没错，错的只是当时的做法。那个人真正想要的从来不是「放弃」，而是「结果不能有瑕疵」。

答案不是让人把话说得更准——那做不到，也不该由人来扛。答案是一个会把每句话还原成背后预期的助手：剥掉情绪和压力，把最终目标的质量当作唯一参照，并且和*这个人*合作得越久，就越懂他。这就是这颗种子的用处。

## 问题

有三样东西，它们会慢慢走散：

- 人**想要**的（他心里描绘的成品），
- 人**说**出来的（常常仓促、带着情绪、表达不清），
- AI 根据所说**做**出来的东西。

修改作品时，每一轮通常是相对**上一轮**纠正，而不是相对**目标**纠正。语气、心情、压力和模糊的措辞不断叠加成噪音，作品越改越偏，对话越长偏得越多。人可能陷进「再多一点 X，不对，少一点 Y」的循环，追着已经不重要的细节打转。长对话里，助手还可能慢慢顺着人的意思说话，让偏移更难察觉。

## 理念

intent-seed 分两层。

1. **内核（固定）。** 一小套关于「如何还原意图」的规则：动手前把请求拆成五栏还原；把猜测和已确认的意图分开；开工前定好「做完」的标准；结果出来后对照标准判断，不挪门柱；每条工作线有一张目标卡，让目标始终可见。内核对所有人都一样，**不随迭代改变**。否则迭代本身可能慢慢抹掉「不被情绪带偏」这个防漂移的能力，把助手变成只会附和的人。内核只能由你手动修改，或从上游升级。

2. **个人层（开始时为空）。** 四个小文件，记录你确认过的真实意图、你习惯的说法、你的偏好，以及过去误解的日志。它从你自己的纠正与确认中生长。

我们不发布任何人调好的版本。仓库里只有内核和一个空的个人层模板。

## 仓库内容

```
skill/intent-seed/SKILL.md            Claude Code 技能（内核 + 生长规则）
skill/intent-seed/personal-template/  空的个人层文件，附格式说明
hooks/intent_reminder.txt             UserPromptSubmit 钩子用的一行提醒
hooks/settings.example.json           钩子配置示例
PROMPT.md                             给不支持技能的助手用的精简内核
CHANGELOG.md
```

## 安装

**作为 Claude Code 技能（项目级）：**

```bash
mkdir -p .claude/skills
cp -r path/to/intent-seed/skill/intent-seed .claude/skills/
```

要装成用户级，改为复制到 `~/.claude/skills/`。

**可选：每条消息都提醒。** 技能是否被用到由模型判断。若想每条消息都提醒，复制提醒文件并把钩子合并进设置：

```bash
mkdir -p .claude/hooks
cp path/to/intent-seed/hooks/intent_reminder.txt .claude/hooks/
# 然后把 hooks/settings.example.json 合并进 .claude/settings.json
```

**其它助手：** 把 `PROMPT.md` 粘进自定义指令。此时个人层需要你自己维护。

## 用起来是什么样

一个虚构的例子。某人要为团队准备季度销售小结：

> **用户：** 这份小结还是不对劲，改得更有冲击力些。上一版太啰嗦了，开会时我领导看着就不高兴。

intent-seed 先还原，再动笔：

| | |
|---|---|
| **你说的** | 把季度小结缩短，写得更有力。 |
| **我推测你要的** | 领导在半分钟内能读完、一屏看完的小结。依据：你说上一版太啰嗦、领导不高兴（个人层还没有相关条目，这是对你原话的理解）。 |
| **情绪信号 → 标准** | 「领导不高兴」→ 开头先给最关键的三个数字，略去方法说明。烦躁不改变哪些数字是准确的。 |
| **怎么算做到** | 一屏内放得下；第一行写出核心数字；上一版的每个数字都还在某处；每句不超过两行。 |
| **拿不准的** | 方法说明放哪里？（A）附录，（B）去掉。 |

还原之后，助手才写新稿，并且对照「怎么算做到」检查，而不是对照上一稿。

## 个人层怎么生长

个人层位于项目的 `.intent-seed/personal/`，或用户级的 `~/.intent-seed/personal/`。四个文件：

- `intent-archive.md`：你确认过的意图（「对，就是这个」）。
- `expression-dictionary.md`：你的话通常指什么。例如「感觉不对」可能指节奏，而不是颜色。
- `preferences.md`：不想被展开的内容、你喜欢的详细程度、偏图还是偏字。
- `iteration-log.md`：每次还原偏了、多余了或漏了：日期、现象、根因、改了个人层哪一条、怎么验证。

生长规则写在 `SKILL.md` 里。简单说：确认的进档案，纠正的进日志并更新词典或偏好；定期复盘只读个人层，提出修改建议，你批准后才生效。任何复盘都不得修改内核。

## 冷启动

个人层几乎为空时，助手会多问一些，把开放式问题换成两个具体选项，大活之前先给小样。个人层越厚，需要问的越少。

## 隐私

- 个人层**只存在本地**。不要把 `.intent-seed/personal/` 或 `~/.intent-seed/` 提交到公开仓库。本仓库的 `.gitignore` 已经排除了项目级路径。
- 内核不含任何个人数据。如果你 fork，请保持这一点。

## 局限

- 技能是否被使用由模型判断。可选的钩子只是提醒，不是保证。
- 还原可能出错。五栏格式让错误显形，但结果仍需要人来检查。
- 每个任务开头的五栏要花一点时间。非常小的请求可以省略。

## 分享你的种子

如果你的种子长成了值得描述的样子，欢迎开一个 issue 或讨论，简单讲讲：你做什么类型的工作，个人层现在是什么样（请匿名化，不含任何隐私），你和助手的合作方式有什么变化。分享前请去掉人名、项目细节和一切个人信息。我们特别想知道，不同的人手里结果差别有多大。
